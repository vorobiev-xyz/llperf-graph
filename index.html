Запросы

Визуализатор отчётов llperf

Перетащите сюда json-отчёт (или несколько) либо нажмите «Открыть отчёты…».

Показывает, что система делала в каждый момент времени: таймлайн запросов по фазам (загрузка модели → prefill → генерация), параллельность, суммарную и поштучную скорость генерации.

Чтобы отчёты из текущего каталога подхватывались автоматически, откройте страницу через локальный сервер: python3 -m http.server → http://localhost:8000/. Справка по каждому блоку — по значку ? рядом с его заголовком.

Управление графиками

  • Колесо мыши над полем графика — масштабирование по времени вокруг курсора. Над подписями осей, легендами и остальной страницей колесо прокручивает страницу как обычно
  • Перетаскивание — сдвиг по времени; двойной клик — весь запуск
  • Наведение — вертикальная линия синхронизирована по всем графикам, в подсказке — срез системы на этот момент
  • Клик по запросу в таймлайне — закрепить/снять выделение
  • Клавиши: ←/→ сдвиг, +/− масштаб, 0 — весь запуск, Esc — снять выделение
  • «Весь запуск» — сбросить масштаб на весь диапазон запуска

Список отчётов

  • Вкладка вверху — переключение между загруженными отчётами
  • × на вкладке — выгрузить отчёт; «Закрыть все» — выгрузить все сразу
  • Перетаскивание вкладки — изменить порядок (он же используется в таблице сравнения)
  • Повторная загрузка файла с тем же именем обновляет отчёт на его месте

Откуда берутся файлы

  • «Открыть отчёты…» или перетаскивание json в окно — работает и при открытии страницы как файла
  • Через локальный сервер: ?file=имя.json (можно несколько) либо файл reports.json рядом со страницей со списком имён

Карточки итогов

  • запросов — число элементов массива metrics; если оно расходится с summary.iterations, показывается и это значение
  • длительность — T = max(request_end_time_ns) − min(request_start_time_ns), реальное время «по стенным часам»
  • параллельность — средняя Σ(e − s) / T, рядом максимум одновременно активных запросов и parallel_size из конфигурации
  • суммарно генерация — Σ response_length / T: пропускная способность всей системы в ток/с
  • на запрос, p50 на запрос, prefill — берутся из summary отчёта (avg_response_tps, p50_response_tps, avg_prompt_tps); если их нет, считаются самостоятельно как Σ токенов / Σ времени соответствующей фазы и медиана по запросам
  • токенов ответа — Σ response_length
  • модель — config.model, в заголовке карточки — config.provider

Полный список величин с формулами — в справке блока «Параметры запуска и итоги».

Обзор запуска

Весь запуск целиком, независимо от текущего масштаба.

  • Полупрозрачные столбики — число активных запросов, зелёная линия — суммарная скорость генерации. Обе величины нормированы на свой максимум за запуск, поэтому шкал нет: полоса нужна для навигации, а не для чтения значений
  • Жёлтая рамка — текущее окно просмотра остальных графиков
  • Потяните мышью — выбрать окно; клик — сдвинуть окно в эту точку, сохранив его ширину; двойной клик — весь запуск

Модель фаз

В отчёте на каждый запрос есть абсолютные метки начала и конца и длительности фаз. Фазы раскладываются от начала запроса в порядке ollama: load_model → prompt_processing → response_generating; остаток до конца запроса — накладные расходы (сеть, сериализация, ожидание клиента). Если сумма фаз почему-то больше длительности запроса, фазы пропорционально сжимаются.

Мгновенная скорость внутри фазы считается постоянной: токены фазы / длительность фазы. Отчёт не содержит потокового отсчёта токенов, поэтому это единственная доступная аппроксимация; при stream: false и request_ttft_ns: null внутренняя динамика запроса неизвестна.

Общее для всех графиков

  • Ось X у всех графиков общая (внизу): время от старта запуска либо время суток — галочка «абсолютное время»
  • Масштаб и сдвиг синхронны, вертикальная линия курсора — тоже
  • В каждом пикселе показывается максимум величины за этот интервал времени, поэтому короткие всплески не пропадают на большом масштабе

Таймлайн запросов

  • Строка — слот исполнения: запросы жадно раскладываются по свободным слотам в порядке старта, число слотов равно максимальной наблюдавшейся параллельности. Снимите галочку «дорожки исполнения» — и каждый запрос получит свою строку (в порядке старта)
  • Полоса — от request_start_time_ns до request_end_time_ns, внутри цветом показаны фазы: загрузка модели, prefill, генерация; серый хвост — накладные расходы
  • Оранжевая риска в начале почти каждой полосы — это фаза load_model_time_ns: ollama сообщает load_duration в каждом ответе (обычно доли секунды)
  • Белая риска — момент первого байта (request_ttft_ns), если он есть в отчёте
  • Подпись внутри полосы (галочка «подписи»): номер запроса · токенов ответа · его скорость; показывается, если полоса достаточно широкая
  • Клик — закрепить запрос (подсвечивается здесь и на графике «Скорость на один запрос»), повторный клик — снять
  • Справа в заголовке — сколько запросов в окне и сколько стартовало/завершилось, а при наведении — сколько активно в точке курсора

Параллельность по фазам

Сколько запросов одновременно находится в системе и чем именно они заняты. Запрос считается активным на интервале [request_start_time_ns, request_end_time_ns].

  • Стек снизу вверх: генерация, prefill, загрузка модели, накладные. Каждый активный запрос в любой момент находится ровно в одной фазе, поэтому высота стека равна общему числу активных запросов
  • Для каждого пикселя берётся момент пиковой загрузки внутри него, и показывается состав фаз именно этого момента — так стек остаётся согласованным, а всплески не теряются
  • Серый пунктир — parallel_size из конфигурации: видно, держится ли нагрузка на пределе или очередь запросов исчерпалась
  • Справа в заголовке — средняя и максимальная параллельность в окне и доля простоя, а при наведении — разбивка по фазам в точке курсора

Суммарная генерация, ток/с

Мгновенная пропускная способность системы: сумма скоростей всех запросов, которые в этот момент генерируют ответ. Скорость одного запроса = response_length / response_generating_time_ns и считается постоянной внутри фазы генерации.

  • Светлая заливка и линия — максимум в пикселе, тёмная линия — минимум: вместе они дают разброс внутри пикселя на грубом масштабе
  • Жёлтый пунктир — среднее по текущему окну: токены, сгенерированные в окне, делённые на его длительность (та же величина в панели «Статистика в окне просмотра»)
  • Провалы обычно совпадают с моментами prefill и с концом запуска, когда слоты освобождаются

Скорость на один запрос, ток/с

  • Отрезок — один запрос: по X его фаза генерации, по Y средняя скорость response_length / response_generating_time_ns
  • График показывает, как параллельность влияет на скорость отдельного запроса: пока все слоты заняты, отрезки лежат плотной полосой, а к концу запуска, когда запросов остаётся мало, скорость растёт
  • Серый пунктир — p50_response_tps из summary (если его нет — медиана, посчитанная по запросам)
  • Выделенный (кликом в таймлайне или в таблице) запрос подсвечивается белым
  • Справа в заголовке при наведении — суммарная скорость, делённая на число генерирующих запросов, то есть средняя скорость активного запроса в этот момент

Обработка промптов (prefill), ток/с

  • Столбик — суммарная скорость prefill: prompt_length / prompt_processing_time_ns, просуммированная по запросам, которые в этот момент обрабатывают промпт
  • Prefill короткий (обычно десятки–сотни миллисекунд) и на порядок быстрее генерации, поэтому вынесен в отдельный график со своей шкалой; за счёт максимума в пикселе всплески видны на любом масштабе, но их ширина на грубом масштабе не отражает реальную длительность
  • Справа в заголовке — сколько токенов промпта обработано в окне и за какое время, а также пик скорости в окне

Статистика: генерация токенов в замере, ток/с

Сравнительные box plot (ящики с усами) для всех загруженных отчётов. Каждый ящик показывает статистическое распределение скорости генерации токенов для запросов одного отчёта в окне просмотра.

Элементы box plot:

  • Ящик — интерквартильный размах (IQR): от Q1 (25%) до Q3 (75%), содержит 50% значений
  • Белая линия внутри ящика — медиана (Q2, 50-й процентиль)
  • Красный ромбик — среднее арифметическое (μ)
  • Усы — минимум и максимум без выбросов (Q1−1.5×IQR и Q3+1.5×IQR)
  • Точки за усами — выбросы (outliers)

Сравнение:

  • Каждый отчёт обозначен своим цветом (см. легенду справа)
  • Под каждым ящиком — название отчёта (наклонно)
  • В легенде: μ = среднее, m = медиана
  • Сравнивайте высоту ящиков (разброс), положение медианы и средних значений
  • Узкий ящик = стабильная производительность, широкий = высокая вариативность

Статистика: общая параллельная генерация токенов, ток/с

Сравнительные box plot показывают распределение суммарной параллельной скорости генерации для каждого отчёта во всех моментах времени в окне.

  • Каждый ящик — один отчёт, 50% значений суммарной скорости (между Q1 и Q3)
  • Медиана — типичная пропускная способность системы
  • Среднее (красный ромбик) — средняя суммарная скорость генерации
  • Сравнивайте общую производительность систем в разных конфигурациях
  • Широкий ящик указывает на нестабильность нагрузки (пики и провалы)
  • Высокая медиана означает стабильно высокую пропускную способность

Статистика: удельная генерация на поток, ток/с

Сравнительные box plot показывают распределение эффективности использования одного потока обработки для каждого отчёта.

  • Каждый ящик — распределение удельной скорости (ток/с на поток) для одного отчёта
  • Медиана — типичная производительность одного потока
  • Среднее — средняя эффективность потока
  • Сравнивайте, как разные конфигурации влияют на производительность одного потока
  • Узкий ящик = стабильная производительность каждого потока
  • Широкий ящик = потоки конкурируют за ресурсы, производительность плавает
  • Низкая удельная скорость при высокой параллельности указывает на bottleneck

Статистическое сравнение запусков

Секция содержит графики-поплавки (box plot) для визуального сравнения производительности всех загруженных отчётов. В отличие от графиков выше, эти графики не привязаны к временной оси и не реагируют на курсор.

Порядок отображения:

  • Порядок ящиков (слева направо) соответствует порядку вкладок отчётов в шапке
  • Перетаскивая вкладки, вы меняете порядок отображения на графиках
  • Каждый отчёт обозначен своим уникальным цветом

Назначение графиков:

  • Генерация токенов — сравнение скорости генерации отдельных запросов
  • Параллельная генерация — сравнение общей пропускной способности систем
  • Удельная генерация — сравнение эффективности одного потока/слота

Используйте эти графики для быстрой оценки: какая конфигурация даёт лучшую производительность, стабильность и эффективность использования ресурсов.

Статистика в окне просмотра

Те же определения, что и в итогах запуска, но всё обрезано по границам видимого окна: от фазы учитывается только попавшая в окно часть, а её токены — пропорционально этой части. Значения пересчитываются при любом изменении масштаба или сдвига.

  • окно, длительность окна — границы и ширина видимого интервала
  • запросов в окне — сколько запросов пересекается с окном; в скобках — сколько в нём стартовало и сколько завершилось
  • параллельность — средняя (суммарное время активности запросов в окне / длительность окна) и максимальная
  • простой — время внутри окна, когда не было ни одного активного запроса, и его доля
  • сгенерировано токенов — Σ (скорость запроса × его время генерации внутри окна)
  • суммарная генерация — эти токены, делённые на длительность окна
  • скорость на запрос (сред.) — средняя скорость генерации, взвешенная по времени генерации в окне
  • машинное время генерации — суммарное время генерации всех запросов внутри окна; «слота в среднем» — оно же, делённое на длительность окна
  • prefill — токены промпта и время prefill, попавшие в окно
  • загрузка модели — сколько фаз загрузки попало в окно и их суммарное время

Параметры запуска и итоги

Первые два блока таблицы — данные отчёта без изменений, третий вычисляется визуализатором из массива metrics. Все длительности в отчёте в наносекундах, здесь переведены в секунды.

config

Словарь параметров запуска из отчёта, ключ → значение, как есть (включая применённые значения по умолчанию). Ничего не пересчитывается.

summary (из отчёта)

Итоги, посчитанные самим измерителем, показаны как есть (округление до 2 знаков). Это средние по одному запросу, а не пропускная способность системы: avg_prompt_tps / p50_prompt_tps / trimmed_avg_prompt_tps — среднее, медиана и среднее без минимума и максимума для скорости обработки промпта; *_response_tps — то же для скорости генерации ответа; iterations — число повторений запроса.

вычислено

Обозначения: s = request_start_time_ns, e = request_end_time_ns, T = длительность запуска, Σ — сумма по всем запросам отчёта.

  • начало запуска — минимальное s, как дата и время суток (метки трактуются как unixtime в наносекундах)
  • длительность запуска T — max(e) − min(s): реальное время «по стенным часам» от старта первого запроса до конца последнего
  • занятых слотов (макс) — максимум одновременно активных запросов; активность запроса — интервал [s, e]
  • средняя параллельность — Σ(e − s) / T, среднее число запросов «в полёте»; сравнивайте с parallel_size
  • простой — суммарная длительность интервалов, где не было ни одного активного запроса, и её доля от T
  • суммарно токенов ответа / промпта — Σ response_length и Σ prompt_length
  • суммарная генерация — Σ response_length / T: пропускная способность всей системы в ток/с. Примерно равна скорости одного запроса, умноженной на среднюю параллельность, и потому в разы больше avg_response_tps
  • время генерации (сумма) — Σ response_generating_time_ns: машинное время по всем слотам, поэтому оно может быть в parallel_size раз больше T
  • время prefill (сумма) — Σ prompt_processing_time_ns
  • время загрузки модели (сумма) — Σ load_model_time_ns (ollama сообщает load_duration в каждом ответе, поэтому слагаемых столько же, сколько запросов)
  • накладные расходы (сумма) — Σ max(0, (e − s) − (load + prompt + generating)): то, что не объясняется фазами провайдера — сеть, сериализация, ожидание клиента

Сравнение загруженных запусков

Строка — один загруженный отчёт, порядок строк совпадает с порядком вкладок (его можно менять перетаскиванием вкладки). Активный отчёт выделен цветом, клик по строке делает отчёт активным. Панель появляется, когда загружено хотя бы два отчёта.

  • запросов — размер массива metrics; parallel — config.parallel_size; модель — config.model
  • длительность — T запуска; сум. ток/с — Σ response_length / T
  • ток/с на запрос и p50 ток/с — avg_response_tps и p50_response_tps из summary; prefill ток/с — avg_prompt_tps
  • макс. паралл. — максимум одновременно активных запросов; простой — доля времени без активных запросов; токенов ответа — Σ response_length

Таблица запросов

  • старт, конец — от начала запуска либо время суток (галочка «абсолютное время»); длит. — e − s; слот — дорожка исполнения из таймлайна
  • промпт, ток / prefill, с / prefill, ток/с — prompt_length, prompt_processing_time_ns и их отношение
  • ответ, ток / генерация, с / ток/с — response_length, response_generating_time_ns и их отношение
  • load, с — load_model_time_ns; накладные, с — остаток длительности запроса, не объяснённый фазами
  • Клик по строке — закрепить запрос (подсветка в таймлайне и на графике скоростей), двойной клик — приблизить окно к этому запросу, клик по заголовку — сортировка
  • Галочка «только попадающие в окно» оставляет запросы, пересекающиеся с окном просмотра; в таблицу выводится не более 500 строк
