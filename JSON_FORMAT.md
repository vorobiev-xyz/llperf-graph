# Формат итогового отчёта
1. Итоговый отчёт сохраняется в файл в формате json с корневым элементом типа "словарь".
2. В корневой элемент кладётся словарь config с параметрами запуска приложения. Ключ - имя параметра, значение - его значение. Публикуются даже применённые значения по умолчанию, кроме не определенных.
3. В корневой элемент кладётся словарь summary с результатами вычисленной производительности.
4. В словарь summary кладётся количество повторений запросов к провайдеру с ключом iterations.
5. В словарь summary кладётся средняя скорость парсинга промпта с ключом avg_prompt_tps, выраженная в токенах в секунду.
6. В словарь summary кладётся медианная скорость парсинга промпта с ключом p50_prompt_tps, выраженная в токенах в секунду.
7. В словарь summary кладётся средняя скорость парсинга промпта, полученная при отбрасывании минимального и максимального значений, с ключом trimmed_avg_prompt_tps, выраженная в токенах в секунду.
8. В словарь summary кладётся средняя скорость генерации ответа с ключом avg_response_tps, выраженная в токенах в секунду.
9. В словарь summary кладётся медианная скорость парсинга ответа с ключом p50_response_tps, выраженная в токенах в секунду.
10. В словарь summary кладётся средняя скорость парсинга ответа, полученная при отбрасывании минимального и максимального значений, с ключом trimmed_avg_response_tps, выраженная в токенах в секунду.
11. В корневой элемент кладётся словарь metrics с результатами каждого запроса в виде массива словарей, где каждый словарь хранит данные по одному запросу.
12. В данные запроса кладётся метка времени начала запроса с ключом request_start_time_ns, выраженная в наносекундах.
13. В данные запроса кладётся метка времени окончания запроса с ключом request_end_time_ns, выраженная в наносекундах.
14. В данные запроса кладётся метка времени получения первого байта ответа с ключом request_ttft_ns, выраженная в наносекундах.
15. В данные запроса кладётся размер промпта с ключом prompt_length, выраженный в токенах.
16. В данные запроса кладётся время обработки промпта с ключом prompt_processing_time_ns, выраженное в наносекундах.
17. В данные запроса кладётся размер ответа с ключом response_length, выраженный в токенах.
18. В данные запроса кладётся время ответа с ключом response_generating_time_ns, выраженное в наносекундах.
19. В данные запроса кладётся время загрузки модели с ключом load_model_time_ns, выраженное в наносекундах.
20. В данные запроса кладётся время обработки запроса с ключом provider_total_time_ns, выраженное в наносекундах.

#### Данные для итогового отчёта, получаемые из ollama
1. В ответе от провайдера по ключу prompt_eval_count находится размер промпта в токенах.
2. В ответе от провайдера по ключу prompt_eval_duration находится время обработки промпта в наносекундах.
3. В ответе от провайдера по ключу eval_count находится размер ответа в токенах.
4. В ответе от провайдера по ключу eval_duration находится время генерации ответа в наносекундах.
5. В ответе от провайдера по ключу load_duration находится время загрузки модели в наносекундах.
6. В ответе от провайдера по ключу total_duration находится общее время обработки запроса в наносекундах.
